# 아두이노 UnoQ 보드 — 포트 및 접속 방법

## Summary

Arduino UnoQ 보드(호스트명 `uno-q`)에서 Debian Linux가 돌고, 그 위에 AgentVault API, UnoQ 모니터링
대시보드, AI 활용 능력 시험 서버, Arduino 코어 서비스가 동시에 떠 있다. 이 문서는
`live_server_info` 폴더의 조사 기록(2026-08-29 SSH 조사)과 이후 변경(2026-09-06 포트 교환)을 합쳐
포트와 접속 방법을 한곳에 정리한 것이다.

- 비밀번호·토큰·API 키는 이 문서에 적지 않았다(`****`로 가림). 실제 값은 원본 폴더에 있다.
- 조사 시점 이후 서버 상태가 바뀌었을 수 있다. 배포 전에는 아래 "현재 상태 다시 확인하기" 명령으로 재확인한다.

### 새 서비스 배포 시 비어 있는 포트

- 8000, 3000: 원래 `arduino-backend`/`arduino-frontend`용이었으나 2026-08-29에 두 서비스를 disable해서 지금은 비어 있다. 단, nginx 설정이 아직 `/api/`, `/docs` → 8000, `/` → 3000으로 보내고 있으므로 이 포트를 쓰면 nginx 80번 경로로도 노출된다.
- 8080, 5000 등도 조사 시점에는 비어 있었다.

## 4. nginx 라우팅 (포트 80)

설정 파일: `/etc/nginx/sites-enabled/arduino-server`

```nginx
upstream backend    { server 127.0.0.1:8000; }
upstream frontend   { server 127.0.0.1:3000; }
upstream agentvault { server 127.0.0.1:8888; }

server {
    listen 80;
    server_name 100.80.214.126 _;

    location /v1/          -> agentvault (127.0.0.1:8888)
    location /admin        -> agentvault (127.0.0.1:8888)
    location /openapi.json -> agentvault (127.0.0.1:8888)
    location /api/         -> backend    (127.0.0.1:8000)   # 현재 서비스 없음
    location /docs         -> backend    (127.0.0.1:8000)   # 현재 서비스 없음
    location /             -> frontend   (127.0.0.1:3000)   # 현재 서비스 없음
}
```

(원본 기록도 location 부분을 요약 표기로 남겼다. 실제 문법은 서버 파일을 확인한다.)

7539, 8887, 9991, 9999는 nginx를 거치지 않고 포트를 직접 열어 외부에 노출된다.

## 8. 프로젝트별 배포 방법

### AgentVault

- 로컬 리포의 `agent_vault/scratch/deploy_to_server.py` 실행 → SSH 동기화, venv 설정, 서비스 재시작까지 처리.
- `.env` 키 목록: `DATABASE_URL`, `ADMIN_TOKEN`, `VAULT_API_KEY`, `ENV=production`, `PORT=8888`, `PUBLIC_PORT=8887` (값은 `****`).
- DB: PostgreSQL `agentvault_licensing`.

### UnoQ 모니터

```bash
# live_server_info/monitor/deploy.sh 가 하는 일
python3 -m py_compile monitor_server.py
scp -o StrictHostKeyChecking=no monitor_server.py arduino@172.30.1.70:/home/arduino/monitor/monitor_server.py
ssh -o StrictHostKeyChecking=no arduino@172.30.1.70 "sudo systemctl restart unoq-monitor && sleep 1 && systemctl is-active unoq-monitor"
```

### AI 활용 능력 시험 서버

`live_server_info/exam-server/`의 `deploy.sh`(사설 IP, rsync), `deploy-tailscale.sh`(Tailscale, rsync),
`deploy-final.sh`(Tailscale, scp)가 있다. 순서는 모두 같다: 원격 폴더 생성 → 파일 전송 → 권한 설정 →
`exam-server.service`를 `/etc/systemd/system/`에 복사 → `daemon-reload` → `enable` + `restart` → `status`.

- 주의: `deploy-final.sh`는 원격 폴더를 `rm -rf`로 비우고 `data/users.json`, `data/results.json`을 `[]`로 초기화한다. 응시 기록이 지워진다.
- 주의: 세 스크립트의 마지막 안내 문구와 `DEPLOYMENT.md`, `START_HERE.md`는 아직 옛 포트 9999로 적혀 있다. 실제 포트는 `server.js`의 `PORT = 9991`이다.
