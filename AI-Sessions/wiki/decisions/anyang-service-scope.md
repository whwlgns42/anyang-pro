# 안양 청년정책 비서 — 수집 대상·프로필·알림·화면 범위 결정

## Summary

수집 대상은 안양시 청년 게시판 1개, 프로필은 생년·성별·직군·재학/재직 여부만, 알림은 사용자별 자유 시각 + on/off로 정한다. 기억 화면(조회·수정·삭제)과 대화 히스토리 목록 화면을 넣고, 인증 부가 테이블은 쓰지 않는다. 가입 시 개인정보 필수 동의 화면(국외 이전 고지)과 처리방침 페이지를 둔다. `ADMIN_EMAILS`로 지정한 관리자용 페이지(수집·발송·사용자·API 사용량)를 두되 대화·기억 원문은 보여주지 않는다.

## Context

설계 draft에서 "확인이 필요한 항목"으로 올렸던 질문에 사용자가 2026-09-27에 답했다. 설계 문서는 이 결정에 맞춰 수정한다. 설계 승인은 별도다.

|---|---|
| 수집 대상 | 안양시 청년 게시판 1개: https://www.anyang.go.kr/youth/selectBbsNttList.do?bbsNo=1184&key=3543 |
| 프로필 항목 | 생년(나이)·성별·직군·재학/재직 여부. 소득 등 그 외 항목은 수집하지 않는다 |
| 알림 | 개인 설정 화면에서 사용자별로 알림 시각을 자유 설정, 알림 on/off |
| 기억 화면 | "AI가 기억하는 내 정보" 화면을 넣는다. 조회·수정·삭제 |
| 대화 히스토리 | 대화 히스토리 목록 화면을 넣는다 |
| 인증 부가 테이블 | `verification_tokens` 등 쓰지 않는다 |
| 개인정보 동의 | 가입 시(Google·이메일 모두) 필수 동의 화면. 수집 항목(생년·성별 등)과 목적, DeepSeek·Gemini 무료 티어로의 국외 이전 고지(Gemini로 대화 내용 전송 포함, user 2026-09-27 — [[anyang-ai-models-data-transfer]]), 동의 시각 기록. 개인정보 처리방침 페이지 포함. 세부 문구·동의 기록 방식은 설계에서 정한다. **화면 표현 변경(user, 2026-09-28)**: 동의 화면·처리방침에서 국가명·서비스명(DeepSeek·Gemini)·상세 고지를 빼고 "AI가 대화 내용을 처리" 수준으로 단순화한다. 실제 전송은 그대로이며 기존 동의 기록은 유지, 재동의 없음(확인 항목 41, 법적 요건은 사용자 확인 대상) |
| 동의 항목 | "수집·이용"과 "국외 이전"을 분리해 각각 받는다. 두 번째 항목의 코드 식별자 `overseas_transfer`와 필수 검증은 유지하고 화면 이름만 "AI 처리"류로 바꾼다(user, 2026-09-28) |
| 처리방침 개정 | 개정 시 재동의를 강제한다. **예외(user, 2026-10-05, 확인 항목 63)**: 보관 기간 고지 추가(대화 마지막 대화 후 1년 자동 삭제, 로그인·가입 시도와 채팅 요청 기록 1일 보관, 대화 기록 화면에서 직접 삭제 가능)는 재동의 없이 개정한다(`POLICY_VERSION` 유지). 이유: 수집 항목·목적·AI 처리 대상을 바꾸지 않고 보관 기간 고지만 추가. 법적 판단은 하지 않았다(2026-09-28 확인 항목 41과 같은 처리) |
| 탈퇴 시 동의 기록 | 즉시 삭제하지 않고 증빙용으로 1년 보관한 뒤 정리 잡으로 삭제한다 |
| 비밀번호 재설정 | 1차 출시에서 제외. Google 로그인으로 대체 안내. 이메일 발송 수단 없음 |
| 공지 자격요건 | 구조화 컬럼은 1차 출시에서 만들지 않는다 |
| 로그 보존 | 수집 실행 이력·외부 API 사용량 기록은 90일 보존 후 정리 잡으로 삭제. 알림 발송 로그는 중복 발송 방지에 쓰이므로 삭제 대상에서 제외 |
| 알림 발송 로그 상태 | 발송 전(`pending`) 상태를 둔다. 세부는 설계에서 정한다 |
| 프로필 선택지 | 직군과 재학/재직 여부를 분리한다. 코드 식별자 확정: `gender` = `male`/`female`/`unspecified`. `enrollment_status` = `student`(학생)/`employed`(재직)/`job_seeking`(구직·미취업)/`other`(기타). `occupation_type`(업종·직무) = `it`(IT·개발)/`manufacturing`(제조·생산)/`service_sales`(서비스·판매)/`office_management`(사무·경영)/`culture_arts`(문화·예술)/`medical_welfare`(의료·복지)/`construction_agriculture`(건설·농업 등)/`other`(기타) |
| 관리자 지정 | 환경변수 `ADMIN_EMAILS`(이메일 목록)에 있는 계정만 관리자. DB 역할 컬럼 없음 |
| 관리자 기능 | ① 공지 수집 관리: 수집 실행 이력·실패 확인, 수동 수집 실행, 잘못 수집된 공지 숨김 ② 알림 발송 현황: 날짜별 발송·실패 수, 구독 수(집계만) ③ 사용자 관리·통계: 가입자 수, 연령대·직군 등 집계, 계정 정지·삭제 ④ 외부 API 사용량: DeepSeek·Gemini 호출 수, 무료 한도 대비 사용량, 오류 현황 |
| 관리자 원칙 | 관리자 API는 서버에서 매 요청 `ADMIN_EMAILS`를 확인한다. 관리자 화면에서도 개인별 대화 내용·기억 원문은 보여주지 않는다 |
| 대화 기록 보관 기간 (user, 2026-10-05, 확인 항목 63) | 마지막 대화(`conversations.updated_at`) 후 1년이 지나면 대화를 자동 삭제한다. AI 기억(`user_preferences`)은 지우지 않는다(출처 연결만 끊김). 처리방침에 적는다 |
| 채팅 사용 제한 (user, 2026-10-05, 확인 항목 63) | 사용자별 1분 5회, 하루 100회(넘으면 429와 "잠시 후 다시 시도해 주세요" 안내), 메시지 2,000자(넘으면 400, 화면에서도 미리 막음) |
| 대화 히스토리 삭제 (user, 2026-10-05, 확인 항목 62) | 대화 기록 화면에서 대화를 하나씩 삭제한다. 5초 동안 "되돌리기"를 제공한다(기억 화면과 같은 방식). 그 대화에서 추출된 AI 기억(`user_preferences`)은 지우지 않고 남긴다(출처 대화 연결만 끊김) |
| 직군 매칭 반영 (user, 2026-10-04, 확인 항목 59) | 알림 매칭에 프로필 직군(`occupation_type`)도 반영한다("직군도 매칭에 반영해줘"). 이전까지 추천·알림은 대화 추출 관심사(`user_preferences`)만 썼고, 프로필 기반 매칭 안(확인 항목 27·33)은 2026-09-28 취소됐었다 — 이 행이 그 "프로필 미사용" 상태를 바꾼다. 관심사가 없고 직군만 있는 사용자도 알림 대상이 된다. 방법(직군 코드별 고정 설명 문장 임베딩, 결합 방식, 임계값)과 추천 목록 반영 여부는 설계·사용자 결정에서 정한다. 사용자 데이터를 외부 AI로 보내지 않는 원칙은 그대로다([[anyang-ai-models-data-transfer]]) |
| 공지 수집 범위 (user, 2026-10-04) | 게시판 전체(약 462건, 1~47페이지)를 한 번 백필하고, 이후 새 글은 분 단위로 반영한다. 제목·본문과 함께 첨부파일은 **링크만** 저장한다(파일명+URL, 파일 복사·OCR 없음, OCR은 확인 항목 24대로 나중). 백필은 로컬 일회성 스크립트로 돌린다 |
| 공지 화면 표시 (user, 2026-10-04) | 사용자 시안대로 고정 공지 별표와 "본문 이미지" 배지를 둘 다 넣는다(기존 설계의 "배지 없음"을 대체). 화면 최신성은 탭 복귀·재진입 시 재조회와 캐시 없는 API로 맞추고, 실시간 연결(Supabase Realtime)은 넣지 않는다 |
