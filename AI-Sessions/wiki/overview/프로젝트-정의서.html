프로젝트명

02

프로젝트 한 줄 정의

안양시 청년이 흩어진 청년정책 공지 속에서 나에게 해당되는 정보를 찾기 어려운 문제를, AI가 공지를 매일 자동으로 모아 이해해 두고 대화로 설명하며 관심사에 맞는 새 공지를 원하는 시각에 알려 주는 방식으로 해결하는 PWA 웹앱을 만든다.

03

해결하고자 하는 문제

문제설명이 서비스의 대응
정보 과다 · 분산청년정책 공지는 양이 많고 흩어져 있어 한눈에 보기 어렵다게시판 공지를 매일 자동 수집해 한곳에 모음
해당 여부 판단내 나이·성별·직군·재학/재직 상황에 맞는 공지인지 스스로 가려내기 어렵다나이대·상황을 반영해 AI가 대화로 설명
새 공지를 놓침게시판을 매번 직접 들어가 확인해야 새 소식을 안다관심사에 맞는 새 공지를 정한 시각에 푸시 알림
근거 확인요약만 보면 원문이 무엇인지 확인하기 어렵다답변과 함께 참고한 공지 카드를 보여 주고, 상세 화면에서 원문 링크 제공
04

핵심 사용자

프로필의 재학/재직 여부 선택지(학생 · 재직 · 구직/미취업 · 기타)를 기준으로 나눈다. 나이대는 19세 미만부터 40세 이상까지 청년정책 구간으로 본다.

사용자필요
구직 · 미취업 청년취업 지원, 구직 활동 지원처럼 지금 신청할 수 있는 정책을 빠르게 알고 싶다
재학 중인 청년학업과 병행할 수 있는 지원, 대상 나이대에 맞는 공지를 가려 보고 싶다
재직 청년바쁜 일과 중 게시판을 확인할 시간이 없어, 필요한 것만 알림으로 받고 싶다
정책 탐색 입문자어떤 지원이 있는지부터 편하게 물어보며 알아가고 싶다
05

MVP 핵심 기능

기능설명우선순위
사용자 기능
AI 정책 상담 채팅질문을 받으면 관련 공지를 찾아(RAG) 나이대·상황 조건을 반영해 답변을 실시간 스트리밍대화형 AI: DeepSeek · 공지 검색: pgvector 유사도필수 · MAIN
근거 공지 카드답변에 사용한 공지를 제목 · 게시일 카드로 답변 위에 표시. 누르면 공지 상세로 이동해 원문 링크 확인필수
추천 공지 목록 · 상세대화에서 쌓인 관심사와 가까운 공지 목록. 관심사가 아직 없으면 최신순필수
맞춤 알림사용자가 알림 시각을 자유롭게 정하고 켜고 끔. 관심사에 맞는 새 공지를 Web Push로 발송필수
AI가 기억하는 내 정보대화에서 추출한 관심사 문장을 조회 · 수정 · 삭제필수
대화 기록지난 대화 목록과 메시지 다시 보기필수
가입 · 프로필 · 동의Google 또는 이메일 가입, 프로필 4항목, 개인정보 동의 2종, 처리방침 페이지, 탈퇴필수
운영 기능
관리자 화면수집 관리(이력 · 수동 수집 · 공지 숨김), 알림 발송 현황, 사용자 통계 · 정지, AI 사용량. 대화 · 기억 원문은 볼 수 없음필수
DB 저장PostgreSQL + pgvector(Supabase 서울 리전)필수
1차 출시 제외 · 보류
비밀번호 재설정이메일 발송 수단이 없어 제외, Google 로그인으로 대체 안내1차 제외
공지 자격요건 구조화연령 · 직군 조건을 별도 칸으로 정리해 필터링하는 기능1차 제외
포스터 이미지 글자 인식이미지로만 된 공지 내용 읽기(OCR)데이터 확인 후 결정
06

자동화 흐름

무거운 일(수집 · 내용 이해 · 알림)은 서버가 정해진 시각에 미리 처리하고, 사용자가 접속했을 때는 준비된 결과를 빠르게 꺼내 쓴다. 예약 실행은 Supabase의 pg_cron이 앱 API를 호출하는 방식이다.

배치

A. 공지 수집 · 이해 파이프라인

서버가 매일 자동 실행, 사용자 입력과 무관

  1. 매일 04:00 예약 작업이 수집을 시작
  2. 안양시 청년 게시판 목록 → 상세 순으로 읽기robots.txt 확인, 요청 사이 2초 간격
  3. 중복 걸러내기제목+본문 해시로 비교해 새 공지 · 바뀐 공지만 저장
  4. 내용 이해(임베딩)제목+본문을 Gemini로 벡터화해 저장, 공지가 바뀌면 다시 처리
  5. 검색 준비 완료채팅 · 추천 · 알림이 이 결과를 함께 사용
배치

A-2. 맞춤 알림 발송

5분마다 자동 실행

  1. 5분마다 지금 알림 받을 시각이 된 사용자 확인자정을 넘기는 시각도 처리
  2. 대상 공지 좁히기알림을 켠 이후 수집된 공지만
  3. 관심사 매칭사용자 관심사 벡터와 공지 벡터의 유사도가 기준 이상인 것만
  4. 중복 방지 기록 후 발송같은 공지는 한 사람에게 한 번만, 등록된 기기마다 Web Push
  5. 결과 기록한 기기라도 성공하면 성공, 실패한 기기 수 함께 기록
실시간

B. 채팅 응답 흐름

사용자가 질문할 때만 실행

  1. 질문 입력
  2. 개인정보 가림전화번호 · 이메일 · 주민등록번호 형태를 AI 전송 전에 가림
  3. 관련 공지 검색질문 + 기존 관심사로 유사한 공지 상위 몇 건, 숨긴 공지 제외
  4. 답변 생성나이대 구간 · 성별 · 직군 조건만 함께 전달(신원정보 없음)
  5. 근거 카드 + 답변 스트리밍
  6. 관심사 기억대화에서 드러난 관심사를 문장으로 요약해 저장 → 추천 · 알림에 반영
실시간

B-2. 추천 목록 서빙

사용자가 목록을 열 때

  1. 접속 로그인 사용자 확인
  2. 이미 처리된 공지 중 관심사와 가까운 것 조회새로 AI를 부르지 않고 저장된 벡터로 계산
  3. 관심사가 없으면 최신 공지순으로 대체
  4. 화면 표시 제목 · 발췌 · 게시일, 상세에서 원문 링크
정리 작업 수집 이력 · AI 사용량 기록은 90일, 로그인 시도 기록은 1일 보관 후 지우는 예약 작업이 준비되어 있다. 되돌릴 수 없는 삭제라 실제 가동 시점은 오너가 따로 정한다. 알림 발송 기록은 중복 방지에 쓰여 지우지 않는다.

08

역할과 진행 방식

사람 한 명이 결정하고, 역할별 AI 개발 에이전트가 설계와 구현을 나눠 맡는다.

역할담당
프로젝트 오너(사용자)범위 · 정책 결정, 설계 승인, 되돌릴 수 없는 작업 승인, 외부 키 준비
pm요청 파악, 작업 분배, 확인이 필요한 항목 관리, 결과 취합
database스키마 · 마이그레이션 · 벡터 인덱스 · 예약 작업 정의
backendAPI 계약, 인증, 채팅 RAG, 수집기, 알림 발송
frontend화면 설계와 구현, PWA
code-review코드와 문서의 모순 검수(수정 권한 없음)
git-manager기능 단위 커밋, push는 승인 후에만
설계→오너 승인→구현 · 테스트→검수→커밋

승인된 설계는 잠기며, 바꾸려면 다시 승인을 받는다.

09

MVP 성공 기준

제안아래 기준은 설계 문서의 동작과 테스트 방법에서 뽑은 제안이다. 오너 확정 전이다.
항목기준
자동 수집예약 작업으로 게시판 공지가 중복 없이 DB에 쌓이고, 바로 검색 가능한 상태가 됨
채팅 품질질문에 관련 공지를 근거 카드와 함께 답하고, 숨긴 공지는 나오지 않음
알림정한 시각에서 5분 안에 도착, 같은 공지 중복 없음, 알림을 켜기 전 공지는 보내지 않음
개인정보외부 AI 요청에 이름 · 이메일 · 계정 ID가 없고, 가림 대상 형태가 가려져 있음
관리자관리자 외 접근 차단, 관리자 화면에 대화 · 기억 원문 없음
보안공개 키로 DB 테이블을 직접 읽을 수 없음, 로그인 시도 제한 동작
10

고도화 방향

방향내용
포스터 글자 인식실제 수집 데이터로 매칭 품질을 본 뒤 이미지 공지 OCR 도입 재검토
프로필 기반 추천대화 전 사용자도 프로필 조건으로 공지를 판정하는 방식. 설계까지 했다가 이번 버전에서는 취소, 필요하면 재검토
공지 자격요건 정리연령 · 직군 조건을 별도 칸으로 구조화해 정확히 거르기
비밀번호 재설정이메일 발송 수단 마련 후 추가
커스텀 도메인서비스 주소를 전용 도메인으로 교체(주소는 환경변수로 받아 코드 변경 없음)
자체 서버 이전Vercel + Supabase에서 보드 서버(UNO Q)로 양방향 전환 가능하게 설계, 전환 시 HTTPS 확보 방법 별도 조사
11

법적 · 개인정보 고려사항

개인정보를 받고 해외 AI를 쓰는 서비스라 따로 항목을 둔다.

항목내용
수집 최소화프로필은 생년 · 성별 · 직군 · 재학/재직 여부만. 소득 등은 받지 않음
동의 분리"수집 · 이용"과 "국외 이전"을 따로 받고 동의 시각을 기록
국외 이전 고지대화 AI(DeepSeek)와 Gemini 무료 티어로의 전송(대화 내용을 AI가 처리)을 가입 시 고지
재동의개인정보 처리방침이 바뀌면 재동의를 강제
외부 전송 원칙이름 · 이메일 · 계정 ID는 외부 AI로 보내지 않음. 출생연도 원값 대신 나이대 구간만 전달, 식별 형태는 정규식으로 가림
탈퇴동의 기록은 증빙용으로 1년 보관 후 삭제
관리자 열람 제한관리자도 개인 대화 · 기억 원문은 볼 수 없고 집계만 봄
수집 예절대상 사이트 robots.txt 확인(제한 없음), 요청 사이 2초 간격
이용 조건Vercel Hobby는 비상업 전용. 수익화 계획 없음, 수익화 시 Pro 전환 필요
